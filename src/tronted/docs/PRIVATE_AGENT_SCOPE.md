# 私有知识库 Agent · 范围说明

聊天页右栏有一块「私有知识库 Agent」展示区。**它只做前端展示，没有任何真实能力。**

这份文档把它的边界写清楚，避免交接时被误认为已经接了 RAG、向量库或文件上传。

---

## 1. 它是什么

答主如果把自己的私有资料整理成知识库，并配一个只在这个知识库上回答的 Agent，来访者就能问「资料里写过的事」，而 Agent 在问题超出范围时明确挡回，不用公开内容硬答。

本工程**只展示这个形态**：三态徽标、知识库主题、可回答范围、出范围提示、示例问题、演示声明。所有这些内容都来自本地夹具，不来自任何接口。

---

## 2. 数据来源

唯一定义在 `src/front/features/private-agent/private-agent-fixture.ts`：

```ts
type PrivateAgentFixture = {
  name: string;             // Agent 名称，由答主自己命名
  topics: string[];         // 知识库主题（只描述范围，不含任何资料内容）
  scope: string[];          // 可回答范围
  sampleQuestions: string[]; // 演示用示例问题
  outOfScopeHint: string;   // 出范围时的兜底说明
};
```

性质：

- **完全确定**：无随机数、无时间戳，同一人物每次渲染结果一致；
- **纯虚构**：不对任何真实用户做「上传过资料」的断言；
- **不含资料内容**：`topics` 只描述范围（「大厂转创业」），不含任何正文、链接或原文片段；
- **默认值是最诚实的值**：未在表中出现的人物一律 `unconfigured`——现实里绝大多数答主还没有配置私有知识库。

内置夹具覆盖 4 位演示人物（`lin-zhixing` / `zhou-yu` / `cheng-che` / `p-shen-yiran`）。

---

## 3. 三态推导

`buildPrivateAgentView(creatorId, creatorName)` 是页面的唯一入口，状态由 `privateAgentStatus()` 推导：

| 状态 | 徽标 | 判定条件 |
|---|---|---|
| `configured` | 已配置 | 主题 ≥ 3 且 范围 ≥ 2 |
| `partial` | 部分配置 | 有夹具，但主题 < 3 或 范围 < 2 |
| `unconfigured` | 尚未配置 | 没有这个人的夹具 |

判定条件刻意与**夹具内容**挂钩而不是写死 ID：调整夹具时状态会自己跟着变，不会出现「夹具已改、状态没改」的漂移。

徽标带 `aria-label="私有知识库状态：<状态>"`，读屏用户不必依赖颜色区分。

---

## 4. 交互边界

界面上的唯一交互是**点示例问题**，效果是 `onPickQuestion(question)` → 填进消息输入框。

因此：

- 不会自动发送（单测断言 `sendMessage` 与 `streamConversationAgent` 均未被调用）；
- 不会发起任何网络请求（这个 feature 目录里没有 `ApiClient` 调用）；
- 未配置时示例问题仍然显示，因为它的语义是「将来可以怎么问」的示意。

**示例问题的措辞刻意与答主的「适合问 TA」不同。** 后者已经渲染在聊天输入区，两处同名会让同一个问句在页面上出现两个可点击入口，键盘与读屏用户无法区分该点哪个。

---

## 5. 必须显示的演示声明

无论哪种状态，面板底部都显示这句（`PRIVATE_AGENT_DEMO_NOTICE`）：

> 演示功能：本区不接入真实私有知识库，不上传文件、不保存私有资料，示例问题只填充输入框。

未配置时另外如实说明「这位答主还没有配置私有知识库……不会发送任何请求」，而不是留白或画一个假装可用的输入框。

---

## 6. 明确不做的事

- 不实现文件上传、解析、切片、嵌入或任何索引流程；
- 不接入向量库、RAG 检索或任何模型调用；
- 不保存、不缓存、不导出任何私有资料；
- 不向服务端发送「谁配置了什么」的查询；
- 不把未配置的人物画成已配置（不为了页面好看而伪造状态）；
- 不把这块展示当成付费咨询的替代或补充能力对外承诺。

`docs/BACKEND_BOUNDARY.md` 已声明后端**不向前端下发任何私有知识库原文**，本展示区不构成对该声明的例外。

---

## 7. 将来接后端时要补什么

如果要做成真功能，前端侧需要的最小改动是：

1. 在 `src/shared/contracts` 新增 `privateAgentSchema`（**只含范围元数据**：状态、主题名、范围名、示例问题），并把「原文永不下发」写成注释约束；
2. 在 `ApiClient` 增加 `getPrivateAgent(creatorId)`，`HttpApiClient` 与 `MockApiClient` 同时实现；
3. `private-agent-fixture.ts` 退化为 Mock 实现的数据源，`buildPrivateAgentView` 改为纯映射（去掉本地判定）；
4. 上传与建库留在服务端，前端不新增任何上传入口——如果产品要做，那是另一个需求，需要单独评估隐私面。

在此之前，本文档描述的就是全部现状。

## 8. 测试覆盖

`tests/features/private-agent.test.tsx`（8 条）：

- 三态推导（含 `partial` 的边界条件）；
- 示例问题不与「答主建议问题」重名；
- 面板按状态渲染主题 / 范围 / 出范围提示 / 演示声明；
- 未配置时如实说明而不是留白；
- 点击示例问题只触发回调；
- 在聊天页里点击后 `sendMessage` / `streamConversationAgent` 未被调用；
- 私有 Agent 面板与咨询面板在右栏共存。
